# 短剧角色管理器

> **核心命题：如何让 AI 在第1集和第80集生成同一个角色？**
>
> 答案是：用 AI 真正"吃"的描述方式锁死视觉特征，而不是用人类感知词汇写一个好看的设定。

## 角色管理的7维锚点系统

### 核心概念：三类描述的 AI 信噪比

AI 视频模型对不同类型的描述，响应精度完全不同。写一堆 AI 不吃的词等于没写：

| 类型 | AI信噪比 | 范例 | 使用策略 |
|------|---------|------|---------|
| 🔴 **数字/比例** | 高 | `168cm`, `7头身`, `比主角矮半个头` | 优先使用 |
| 🟡 **形状/颜色** | 中高 | `鹅蛋脸`, `深棕色`, `月白色` | 固定描述，原样复制 |
| 🟢 **材质/纹理** | 中 | `哑光`, `纱质`, `银质` | 作为补充 |
| ❌ **感受词汇** | 零 | `气质清冷`, `眼神灵动`, `气场强大` | **禁止使用**——AI 读不懂 |

## 第一步：创建角色——7维结构化档案

当用户说"创建一个角色"或"添加角色"时，逐维度收集信息。

### 维度1：面部锚点（🔴 最高优先级）

面部是跨集漂移最大的区域。5个不可变锚点必须在每集 prompt 中**原样重复**：

| 序号 | 锚点 | 精度要求 | 范例 |
|------|------|---------|------|
| 1 | 脸型 | 几何分类 | `鹅蛋脸，下颌线柔和但线条清晰` |
| 2 | 眼型+颜色 | 具体形状+色号 | `杏仁眼，深棕色虹膜，双眼皮宽度约2mm` |
| 3 | 眉形+眉色 | 精确形状+比发色关系 | `柳叶眉，黑色（比发色深1号），眉尾自然收细` |
| 4 | 鼻梁+鼻头 | 侧脸穿帮全靠鼻子 | `鼻梁挺直且窄，鼻头小巧微翘` |
| 5 | 发型+发色 | 观众识别第一信号 | `及腰黑长直，三七偏分，无刘海，发尾齐平` |

**可选附加锚点**（有识别特征的角色才加）：胎记/痣/伤疤/虎牙/酒窝/对耳轮缺口。一旦加上，全剧不能消失。

### 维度2：身高体态（数字化比例）

| 要素 | 锁定方式 | 范例 |
|------|---------|------|
| 绝对身高 | 精确 cm | `168cm` |
| 相对身高 | 以第一主角为基准 | `比陈代码(178cm)矮半个头` |
| 头身比 | 数字 | `约7头身` |
| 肩宽 | cm 范围 | `窄肩(37-39cm)` |
| 体型比例 | 数字比例 | `胸腰臀比约0.7` |

### 维度3：体态签名

每个角色只有一句"体态签名"。这句话翻译为 AI 可读的物理描述。

```
体态签名 = 这个人怎么存在于空间里
AI翻译 = 具体的站姿 + 重心 + 空间占有方式

范例：
"站着像一根线轻轻垂在那里" 
→ slim upright posture, weight on left leg, minimal space occupation
```

**5个固定姿态描述：**
- 默认站姿（重心分配+骨盆倾斜）
- 走路姿态（步幅+步频+手臂摆动）
- 坐下姿态（腿位+手位+背靠习惯）
- 转头习惯（转颈 vs 转身）
- 手势库（3个固定手势+触发条件）

### 维度4：服饰锚点系统

| 子类型 | 规则 | 
|--------|------|
| 🔴 核心锚物 | 每集必出现，全剧不变（发簪/项坠/眼镜/戒指/耳饰之一） |
| 🟡 配色DNA | 3-5色固定色盘，标注禁用色 |
| 🟢 场景服饰 | 按场景分类（日常/战斗/正式/卧床） |
| 材质偏好 | 固定材质范围，标注禁用材质 |
| 裁剪习惯 | 领口/袖口/腰线的个人偏好 |

### 维度5：动态形变规则

角色在运动/战斗/情绪激动时会形变。这些形变不是随机的——需要预设规律：

- 战斗/施法：发力起始部位、重心转移方向
- 奔跑：步幅放大比例、手臂幅度变化
- 情绪激动：面部肌肉启动顺序（如苏清雪是眉尾先跳）
- 躺下/侧卧：头发散落方式、身体曲线变化

### 维度6：角色关系网络

- **关系矩阵**：N×N 矩阵，标注当前关系+关键转折事件
- **关系演变时间线**：带剧集编号的事件链
- **三角冲突检测**：自动发现不合理的关系跳跃

### 维度7：成长刻度尺

按每10集一个里程碑记录角色状态变化，防止角色在剧中途"突然变了"。

## 第二步：结构化存档

创建完成后，角色保存到 `characters/<项目名>/<角色名>.yaml`。

**为什么 YAML 而不是 Markdown**：AI 可以同时读取 YAML 的结构化字段和 Markdown 的自然语言，但 YAML 在程序化检索时更可靠。

**存档完整性检查**——保存前验证：
- [ ] 面部5锚点全部填写
- [ ] 身高有绝对值和相对值
- [ ] 体态签名+AI翻译都有
- [ ] 核心锚物已指定
- [ ] 配色DNA含至少3个主色+1个禁用色
- [ ] 文件编码为 UTF-8

---

## 第三步：一致性检查

使用 `scripts/consistency_check.py` 对已有多集 prompt 自动扫描：

```bash
python scripts/consistency_check.py characters/仙界逆袭/苏清雪.yaml scenes/ep*.md
```

检查项目：
1. 面部锚点是否在每集 prompt 中出现
2. 核心锚物是否被遗漏
3. 身高描述是否有漂移（跨文件检测数字不一致）
4. 禁用色是否出现
5. 感受词汇是否被滥用（`气质|气场|眼神` 等零信噪比词）

---

## 第四步：注入下游

角色数据不是终点。用 `scripts/prompt_inject.py` 把角色锚点自动注入分镜/视频 prompt：

```bash
# 注入到单个分镜
python scripts/prompt_inject.py characters/仙界逆袭/苏清雪.yaml scene_15.md --output scene_15_injected.md

# 批量注入
python scripts/prompt_inject.py characters/仙界逆袭/苏清雪.yaml scenes/ep15_*.md --output injected/
```

注入策略：
- 正面/侧面/背面镜头自动选择对应的面部描述片段
- 全景/中景/特写自动调整锚点详细程度
- 多角色同框自动检查身高差和锚物是否冲突

## 绝对禁区

- ❌ **禁止感受词汇描述外貌**："气质出尘""冷艳高贵""仙气飘飘"
- ❌ **禁止模糊比例**："身材高挑""五官精致""相貌出众"
- ❌ **禁止省略锚点**："前面的描述就不重复了"——AI 不记得上一集写了什么
- ❌ **禁止跨剧混用锚物**：A剧的发簪不能出现在B剧的角色上
